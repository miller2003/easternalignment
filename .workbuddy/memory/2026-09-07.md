## SERP 头像机制诊断（截图 mystic-raj 右侧头像）

经核查：
- mystic-raj 右侧头像 = 站点 Person（SaraH）+ image=sarah-avatar.jpg（MD5 唯一，非 mystic-raj 自身头像）
- mystic-raj frontmatter avatarUrl 指向 /avatars/keen/mystic-raj-on-keen-review-2026.jpg（1.7M 大小，亚裔男图），与右侧老妇人头像不同文件
- BaseLayout 在每页输出 personSchema { @type: Person, name: Sarah, image: sarah-avatar.jpg, url: /about/ }，所有页面继承

**为何只有 mystic-raj 显示**：
- mystic-raj 命中精确人名查询 + Google 在普通 web result 中**对命中导航式查询的 Article+Person schema 触发 author rich result 缩略图**
- 同站点不同搜索/不同结果之间 Google **去重同 Person image**（同站点不会重复展示同一作者缩略图）
- asknebula/eMystics 等竞品页面未声明 author Person → 不触发缩略图

**要让其他 advisor 页也显示头像 → 必须让每位顾问各自成为 Person KG 实体（不是 Sarah 重复）**：
- P0 最小动作（低风险）：为每 advisor md 补 `ogImage: /avatars/<platform>/<slug>.jpg`，让 og:image 每页唯一（当前仅少数 advisor md 有该字段）
- P1 中等动作：ReviewLayout Article JSON-LD 加 `about: [{@type: Person, name: readerLabel, image: absoluteAvatarUrl, jobTitle, worksFor}]` 独立实体（@id 区分 #sarah 与 #reader-X），同时设 sameAs 占位数组 → 强化 KG 实体识别
- P2：填充 Person.sameAs 真实社会账号（Sarah LinkedIn/Twitter；顾问在平台上的 profile URL） → 长期 KG 注册

注意：单条 SERP 头像是否显示最终由 Google 抽样决定，但 P0+P1+P2 全做能最大化每个 advisor 实体被 KG 注册的概率与作者缩略图触发面。
