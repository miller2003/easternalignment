## GEO / AI 引用机制的诊断（用户提问：为什么没做 GEO 也被 AI 选中）

写了 `scratch/geo_text_ratio.py` —— 测量已构建 HTML 中「正文（.prose 内）」vs「全站 chrome」的词数占比，
用于判断页面在 AI 检索下的文本稀释程度。用法：
`python scratch/geo_text_ratio.py dist/<path>/index.html`

### 实测结果（dist/ 已构建页面）
| 页面 | 正文词数 | chrome 词数 | chrome 占比 |
|---|---|---|---|
| reviews/keen | 7,989 | 621 | 7.2% |
| guides/how-to-spot-fake-psychic | 2,792 | 742 | 21.0% |
| guides/karmic-relationships-signs-and-lessons | 1,660 | 733 | 30.6% |
| guides/brutally-honest-psychics-keen | 1,557 | 724 | 31.7% |

**chrome 恒定在 620–740 词**（两遍导航 + disclosure bar + offer bar + 双侧栏 + SideDock + EndCTA + AuthorBio），
所以正文长度直接决定稀释比。**正文 < ~1,500 词 → chrome > 30%**。

### 已确认的具体问题
1. 导航 DOM 渲染**两遍**（桌面 + 移动同时输出 HTML），同一串链接出现两次 → 可砍 15–20% chrome。
2. SideDock 折叠面板（含两个 alt 平台 offer 文案）全量输出在初始 HTML，用户从没展开过也算进 token。
3. `InlineCta` 按「第 2 个 H2 前」自动插入，可能切断 H2 与答案之间的语义单元 —— 这是伤害最大的 CTA 位置。
4. how-to-spot-fake-psychic **前 ~90 词全是 chrome**，正文首字在第 100 词左右，而开头是抽取器加权最重的位置。

### 结论（已答复用户）
- AI 引用 = 检索（相对排序，吃传统 SEO）+ 抽取（绝对判断「这段能答吗」，吃内容形态）。
  用户踩中的是第二阶段，与 GEO 表层技巧（llms.txt / AI 摘要块 / schema 堆叠）无关。
- 被引用后：**锁 URL / H1 / 被引用那一段的措辞**；CTA、样式、内链可随意改；补新事实是加法，安全。
- CTA 不会导致「被抛弃」，不存在联盟站惩罚。机制是 token 稀释 → 语义向量朝商业化 query 漂移。

## 底部栏 → 右侧悬浮 Dock（用户要求，14:00–14:50 完成）

**动因**：原 `StickyCTA.astro`（全宽固定底栏）遮挡正文最后几行文字，用户判定「太差了」。

**改动**
- 新建 `src/components/SideDock.astro`，删除 `src/components/StickyCTA.astro`（git 可恢复，删除前为 clean 状态）。
- `BaseLayout.astro` 的 `stickyCta` prop 语义不变，仅把底栏换成右边缘 dock —— 下游 layout（Article/Review/Comparison）**零改动**。
- Dock = [面板 302px][竖向把手 44px] 一个 flex row 整体平移：
  初始 `translate(100%)` 完全在屏外 → 650ms 后 `is-mounted` 只露 44px 把手 → `is-open` 时 `translate(0)` 从边缘抽出。
- **触发阈值** `OPEN_AT = 0.70` / `CLOSE_BELOW = 0.62`（滞回防抖）。
  progress = `(scrollY - contentTop) / (contentHeight - innerHeight)`；
  内容根优先级：`.article-content` → `.review-content` → `.prose` → `main` → `body`。
- **状态机**：`suppressed`（手动收起后不再自动展开）/ `pinned`（手动展开后不自动收起）。
  X / Esc / 点击外部 = 收起 + `suppressed=true`（**不再整页消失**，避免误触丢失 CTA —— 与旧底栏语义不同）。
  ⚠️ 连带后果：`window.__eaStickyDismissed` 不再被设置 → `InlineCta` 中段注入回到默认行为（总是注入）。
- 把手左缘 3px 金色进度轨 = 实时阅读进度（`--p` CSS 变量），让 70% 阈值可见而非突兀。

**把手文案决策**：用户提议 "have a try"，未采用。理由 ①非美式地道说法（应为 give it a try）；
②项目原则「不要共情，要诊断」——把手仅 ~190px 竖向空间，唯一任务是说明里面是什么。
改为平台具体 offer：Kasamba `3 Free Minutes` / Purple Garden `$30 Free Credit` / Keen `5 Min for $1`。
保留 `tabLabel` prop 可逐页覆盖。

**验证**：`npm run build` 通过（24.48s，无 error/warn）。dist 全站 `sticky-cta` 残留 = 0；
首页 / guides / 三平台 hub 均渲染 `id="side-dock"`，offer 文案与 `/go/` 链接随平台正确切换。
产物 CSS 落在 `dist/_astro/BaseLayout.*.css`。交互预览：`dev/side-dock-preview.html`。

**已知 trade-off（GEO）**：面板（含两个 alt 平台 offer）全量在初始 HTML，约 +48 词 chrome，
已被同日 GEO 诊断列为稀释项之一。若要消除：把 `.sd-panel__alts` 移入 `<template>`，首次展开时 JS 克隆注入
（innerText 提取器读不到 template 内容）。仅省 ~15 词，收益有限，未做。

  用户紧接着说「那个右边侧边边缘的小部件」，即认可右边缘位置 —— **位置未改**（右边缘垂直居中）。

**最终形态 `src/components/SideOfferTab.astro`**（删除 `SideDock.astro`）：
- 40px 宽竖向 tab = 平台 logo(24) + 竖排 offer 文案 + ↗ 图标，**本身就是 `<a>` 直达 /go/**。
- **零 JavaScript**：入场动画用独立属性 `translate: 100% -50%` → `translate: 0 -50%`（`animation ... forwards`），
  这样 `transform`/`scale` 仍可用于 hover。⚠️ 关键技巧：`animation-fill-mode: forwards` 会压过所有普通声明，
  所以 hover 位移**不能也用 `translate`**，必须用 `transform: translateX(-3px)`（两者合成，translate 先于 transform）。
- 删除：面板、alt 平台两行、关闭按钮、滚动监听、70% 阈值、进度轨、脉冲点、Esc/外部点击。
- 保留：5.2s 慢速光扫 `::after`、hover 左移 3px + 提亮、`prefers-reduced-motion` 降级。

**踩坑：`stickyCta.label` 不能直接给竖排 tab 用。**
`ReviewLayout` / `ComparisonLayout` 传的是横向按钮文案（`"Try Keen · 5 min for $1 →"`，25 字符），
竖排会把 tab 撑到 ~190px 且 `→` 与箭头图标重复。
**修法**：`BaseLayout` **不再转发 `label`**，tab 只按 `stickyCta.platform` 自己推导短文案。
（连带：`StickyCtaConfig.label` / `.prompt` 与两个 layout 里的 `platformOffers` / `comparisonStickCopy`
copy map 现在是死代码，未清理 —— 保留接口以防回退。）

**体积**：tab 仅 760 字节 / 可见 3 词。dist/index.html 92,856 → 88,400 字节（比面板版省 ~4.5KB/页），
chrome 稀释问题随之缓解（原「+48 词」降为 ~11 词 aria-label + 3 词可见文案）。

### ⚠️ 构建纪律（本次踩了大坑，务必遵守）
1. **只能用 `run_in_background: true` 跑 build**。用 `npm run build &` + `sleep` 的写法，
   工具调用返回时 shell 退出会 **SIGTERM 掉构建进程**：Astro 会打印「✓ Completed in 1.69s」
   但 **dist 已被清空且未重新生成**（本次 dist 从 602 文件掉到 7 个，靠重跑救回）。
2. 构建**打完页面后进程不退出**（停在 sitemap 阶段），属正常。判据是日志出现 `✓ Completed in XXs`
   **且** `find dist -name "*.html" | wc -l` ≈ 531。两者都满足后再 `pkill -9 -f "astro build"`。
3. 残留的孤儿 node/esbuild 进程会让后续构建卡在 `Collecting build info...` —— 先 `kill -9` 掉 14:12/14:43 那批 PID。
