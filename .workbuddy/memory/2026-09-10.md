## 追加：/go 规则三约束明确后的改造（同日）

**用户明确 /go 规则原本目的**：① 联盟链接不泄露 ② 防 bot 污染数据 ③ **AI app 内置浏览器必须丝滑**。

**核心判断**：防 bot 的**主力不是 Cloudflare，而是 `/go` 页自身的 JS 三重门禁**
（不执行 JS 的爬虫永远触发不到跳转）。CF 按 Referer 的质询对 bot 增量拦截很小，
却误伤去 Referer 的真人 → 放宽安全。

**新规则表达式（Skip，排在现有 /go 规则之前）**：
```
http.request.uri.path contains "/go/"
and (http.request.uri.query contains "ea_sub="
     or lower(http.request.headers["sec-fetch-site"]) in {"same-origin" "same-site"})
```
选 `Sec-Fetch-Site` 而不是 Referer 的理由：它由浏览器自动附加，**不受 Referrer-Policy 影响，
App 内置浏览器也会发**。配套必须加 `/go/*` 限速 30 次/分/IP（因为 ea_sub 可伪造）。

**⚠️ 修掉一个真实漏网**：`ea_sub` 之前只在 `distinctId` 存在时才加，
**SDK 未就绪时整个缺失 → 这类真人必然吃满 CF 质询**（实测 9/9 三次点击里就有一次 `click_id` 为空）。
现改为永远存在，兜底 `anon-<随机>`；postback 识别 `anon-` 前缀按孤儿处理，不建垃圾档案。

**新增 `public/_routes.json`**：有 `functions/` 时默认**每个请求（含静态资源）都触发 Functions 调用**。
排除 `/_astro/*`、`/avatars/*`、`/logos/*`、`/images/*`、`/fonts/*` + 4 个根文件；
**HTML 页面与 /go/ 不排除**，www→顶点域的中间件仍覆盖所有页面。

**Bot Fight Mode 是隐形杀手**：AI 内置浏览器 UA 带 `ChatGPT`/`Instagram`/`FBAN`/`Twitter` 特征易被判 bot，
且**免费版不能按路径排除、一开全站生效** → 建议关闭或改 Allow+日志。

**明确不建议**：把 /go 改成 302 Function —— 虽能让 URL 结构性不泄露且快 200–300ms，
但**防 bot 会变弱**（curl 拿到凭证跟着 302 就能产生真实点击，今天的 JS 跳转天然免疫）。

## Markdown for Agents 落地（同日，AI 可发现性最后一项）

**背景**：`isitagentready.com` 扫描 22 项 → PASS 4 / FAIL 13 / NEUTRAL 5（等级 2 Bot-Aware）。
其中 10 项要求"你是 API/智能体服务"，与内容站无关，**明确跳过**（CF 面板自己也写着
「如果您的站点没有 API，请跳过此步骤」）；`dnsAid` 暂跳过（需 DNSSEC + 智能体服务）。
真正要做的只有 2 项：`linkHeaders`（已做，见上一节）+ `markdownNegotiation`。

**架构决策：在边缘做内容协商，而不是构建期产出 .md 文件**
- 不产生第二个 URL → **没有重复内容的 SEO 风险**，也不用动 sitemap
- 不往 dist 塞上千个 .md → 部署体积与构建时长不变
- **完全不需要改构建**（`package.json` 的 build 一个字没动）
- 代价是运行时 CPU —— 已按 Workers 免费版 10ms/请求的硬上限做了完整测准与限流

**新增文件**
- `functions/_lib/html-to-md.js`（477 行，零依赖）—— 转 `/` 开头的目录**不会被 Pages 当成路由**，
  这是官方推荐的共享代码放法
- `functions/_middleware.js` —— 在原有 www→apex 301 之外加了内容协商
- `scripts/test-markdown-for-agents.mjs` + `npm run test:agents`（已加 .gitignore 白名单）

**关键实现要点（改代码时别破坏）**
1. **只输出正文**：先正则切出 `<main>`，再只对这段分词，并剥掉其中的 `aside/nav/header/footer`
   与 class 命中 `toc|breadcrumb|sr-only|pagination…` 的元素。这是引用准确率的关键。
2. **分词前必须先剥 script/style/注释** —— 这是**正确性前提**而非优化：
   内联 JS 里的 `a < b`、字符串里的 `'</div>'` 会被分词器当成标签、把标签栈搞乱，
   导致"是否处于丢弃子树"永久失效、**整页输出变空**（/comparisons/ 实测踩到）。
3. **丢弃子树用 O(1) 计数器**，且弹栈时把被移除的丢弃帧一并减掉 —— Workders 免费版只有 10ms CPU。
4. **绝不能复用已被 `res.text()` 消费的 Response** 构造新响应，否则抛
   `body object should not be disturbed`（超体积阈值分支必现，回归测试已锁）。
5. 标题里的 `<br>` 要变空格，否则 `Finding Clarity in <br> Online…` 被劈成两行、与 h1 去重失效。

**性能实测（纯转换 CPU，多次取中位数）**
`≈0.04ms/KB`：108KB→2.9ms ・ 137KB→5.1ms ・ 235KB→9.0ms ・ 290KB→11.9ms。
10ms 上限对应约 250KB；**`MAX_CONVERT_BYTES = 150KB`** → 最差约 5.5ms、**留 45% 余量**
（本机 Node 只是代理指标，Workers 实际值有差异，安全系数不能省）。
覆盖率：561 页里 **557 页（99.3%）** 会转 markdown，只有 4 页超标退回 HTML。
（顺带优化掉两处大浪费：每次 `new RegExp` 建属性正则 → 改成缓存；
`stripRawBlocks` 被重复执行两遍 → 加 `stripped` 选项。这两项把 290KB 页从 33ms 压到 12ms。）

**测试**：17 项中间件分支 + 9 个真实页面转换质量 + CPU 基准，全部通过。
**为什么必须用真实 dist 产物测**：上面 4 个 bug 全是真实页面暴露的，合成样例测不出来。

**性能优化过程（分阶段剖析后的结论，值得复用）**
先做了分阶段计时，发现瓶颈**不在分词**（234KB 页仅 7k token），而在**渲染循环**：
extractMain 3.0ms vs htmlToMarkdown 10.1ms。据此做了两处针对性优化：
1. **透明标签快速通道** —— `div`/`span` 是页面上最密集的标签，却要走完整条 20+ 项的 if 链
   才落到末尾。给它们一条 early-return：渲染阶段 10.06 → 8.42ms（−16%）。
   ⚠️ 加快速通道时**必须把旧逻辑里所有会 flush 的容器标签补全**，漏一个就会把两段文字连成一行。
2. **`<svg>` 预剥离** —— 占页面体积约 7% 且 token 密集，整段切掉再分词。
   注意：这条**第一次试验时是负收益**，因为当时 `stripRawBlocks` 被重复执行了两遍；
   修掉重复后才变成正收益。**教训：优化必须先消除浪费，再谈新增手段，否则会得出错误结论。**
另修掉两处大浪费：属性正则每次 `new RegExp` → 改缓存（并顺手把 `\bid\b` 收紧成前置空白，
避免把 `data-page-node-id` 误认成 id 属性）；`stripRawBlocks` 重复执行 → 加 `stripped` 选项。

## ⚠️ 改动影响核对：访客体验（同日，用户要求「确保不影响」）

用户（非技术）明确要求确保改动不影响**网站明面上的东西和访客体验**。
做法：**先在线上测出「改造前」的真实响应头基线，再逐项比对**，不靠推断。

**线上实测基线（curl 未部署版本）**：
- HTML：`cache-control: public, max-age=0, must-revalidate` + `x-content-type-options: nosniff`
  + `referrer-policy: strict-origin-when-cross-origin`
- `/avatars`、`/logos`：`cache-control: public, max-age=14400, must-revalidate` + **ETag**
- `/go/*`：`referrer-policy: same-origin`（不向联盟泄露来源，须保留）
- `/sitemap.xml` 返回 **404**（真实站点地图是 `sitemap-index.xml`，robots.txt 指向正确）

**🔴 我引入又撤掉的一处真回归（重要教训）**：
`_headers` 里把 `/avatars /logos /images` 设为 `max-age=604800`（7 天），
但**线上真实基线只有 14400（4 小时）**。站点 `avatars/` 有 **40MB**，
且由 `scripts/fetch-reader-avatars.mjs` **原地更新、文件名不变** →
7 天会导致「换图后旧图滞留最多 7 天」。**已删除这些规则，回到平台默认**。
**教训：写响应头之前必须 curl 一次线上基线。平台默认值不等于你猜的值。**

**逐项核对结论（均可复现）**：
| 改动 | 是否影响访客 | 依据 |
