### 🔴 本轮发现的真实产品缺陷：每日牌不幂等

`drawDailyCard()` 是「种子哈希 + 跳过近 14 天出现过的牌」，但**跳过列表里包含今天自己那张**。
`storeDailyCard()` 永远把今天放首位，于是第二次调用会跳过它、顺延到下一张候选 →
**同一天抽两次得到两张不同的牌**。`app.ts` 虽先用 `getTodaysCard()` 兜底，但只要历史被
部分清理（隐私模式 / 手动清 storage / 多 tab 写入竞争）就退化成重抽，
工具从「占卜」退化成「随机数生成器」。

修复：拆出纯函数 `pickDailyCard(date, anonymousId, avoidRecentIds)`，
**幂等由函数自己保证，不依赖调用方缓存命中**；`drawDailyCard()` 负责把「今天」
从避重列表剔除。签名向后兼容，调用方零改动。

### 工程坑（本轮新增）
- **`mv dist <bak>` 报 `Device or resource busy`，但 `os.listdir` 下所有子项都能改名**
  → 根因是**某个进程持有 `dist` 目录本身的句柄**（疑似 WorkBuddy 文件监视器），
  与子项无关。**解法**：`cp -r dist/. <bak>` 做备份（校验 934/564 一致），
  再用 Python `shutil.rmtree` 逐项清空 `dist` 内容后原地重建。
  **不要浪费时间反复重试 `mv`。**
- **测试跑完会遗留 `esbuild.exe` 孤儿进程持有工作区** → 导致后续 `mv` 失败。
  枚举 + 强杀用 Python ctypes（`EnumProcesses` + `OpenProcess(PROCESS_TERMINATE)`）
  脚本写在 `scratch/_tmp/killesbuild.py` 思路上；`Stop-Process` 对它们无效。
- **编辑 `askUniverse.ts` 的数组时，`Edit` 把注释与代码挤到同一行**
  （`// 3. 替代说法与自伤    'self[- ]?harm',`）→ 静默吞掉了一整类自伤词表。
  数组型字面量编辑后**必须回读确认换行完好**，不能只看「Successfully edited」。
- **`agent-browser` 之外，`du -sh` 在 Git Bash 下遍历目录也极慢且易被 SIGTERM**，
  统计体积优先用 `find | wc -l` 或 Python。
- 一条测试断言把 `-` 当词边界：`/\b...reading\b/i` 命中 `find-ahelpline` 里的 `ahelp`？
  不是 —— 实际是 `self-harm` 的连字符让 `\b` 位置偏移。**含连字符的文案做正则断言前先 `replace(/-/g,'')`**。
- 危机文案断言**不能用「是否含 reading」** —— 文案里 "please stop **reading** here"
  是合法劝阻语。断言要盯**商业语境词**（advisor/psychic/buy/offer/free minutes…），
  不是单字面词。
