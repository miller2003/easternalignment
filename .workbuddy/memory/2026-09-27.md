# 2026-09-27 工作日志

## 排查「PostHog 录像里 logo / 图片全是破图」

**结论：真实用户不受影响；破图是 Cloudflare「Hotlink Protection（防盗链）」拦截 PostHog 回放器的跨域取图造成的。**

### 决定性证据（curl 线上实测）
| 请求 Referer | /logo.jpg 结果 |
|---|---|
| `https://easternalignment.com/`（同源，真实用户） | **200**，105441 B |
| 无 Referer | **200** |
| `https://www.easternalignment.com/`（同站子域） | **200** |
| `https://us.posthog.com/` | **403**，响应体 `error code: 1011` |
| `https://app.posthog.com/` / `https://posthog.com/` | 403 |
| `https://www.google.com/` / `https://www.bing.com/` / `https://t.co/` | 403 |
| `https://easternalignment.pages.dev/`（预览域） | 403 |

- 403 响应头带 `Vary: referer` + `Cache-Control: no-store`，是 Cloudflare 边缘注入，非站点代码。
- `error code: 1011` = CF 官方「Hotlink Protection / 防盗链」错误码 → 归属 Scrape Shield，非 WAF 自定义规则。
- **仅图片受限**：`/_astro/*.css` 跨域 Referer 实测 200；但 `favicon.png`、`/avatars/*.jpg` 同样 403 → 拦截按资源类型（图片）生效。
- `public/_headers` 与 `functions/` 里均无 referer 判断逻辑，可排除站点侧代码。

### 机理
PostHog 回放（rrweb）**不录制图片像素**，只序列化 `<img src>`；回放到 `us.posthog.com` 的播放器 iframe 里时，浏览器会**以 posthog.com 为 Referer 重新请求原图** → 被 CF 防盗链 403 → 显示破图三角形。因此破图是回放侧的必然结果，不代表线上故障。

### 影响面
1. **用户访问本站：无影响**（同源 Referer 恒为 200）。
2. **PostHog 会话回放 / 热图：图片全丢**，UX 排查时无法看到图片布局（本项目诊断能力受损）。
3. **搜索引擎图片 / 站外链接预览：存在客观损失**。Google/Bing 图片代理带自家 Referer → 403，站内图片难以进入图片搜索索引；社交/IM 预览爬虫多数不带 Referer（这部分通常仍正常）。

### 待用户执行的修复（改 CF 后台，非代码）
- CF Dashboard → easternalignment.com 所在 zone → **Scrape Shield → Hotlink Protection → 关闭**。零代码变更、即刻恢复回放清晰度；代价是第三方可直接盗链图片（本站图片体量小，风险有限）。
- 若必须保留防盗链：Hotlink Protection 无白名单 UI，需改为 **WAF 自定义规则**（或 Transform Rule）自行实现 allowlist：放行「无 Referer」「Referer 含 easternalignment.com」「Referer 含 posthog.com」，再拦其余图片请求。
- 建议同步在 CF **Security Events / 缓存分析**里按 `error 1011` 复核拦截量，确认是否有非预期来源被拦。
